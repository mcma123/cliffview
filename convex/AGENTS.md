# convex

## Purpose

The Convex backend for the academy: schema, server functions, and the deployment-target contract. Schema and the admin read surface are live on prod; the React app does not consume them yet.

## Ownership

- Owns everything under `convex/`, the deployment target, and the Convex CLI workflow
- Owns the `CONVEX_DEPLOYMENT`, `VITE_CONVEX_URL`, and `VITE_CONVEX_SITE_URL` values in `.env.local`
- Does not own the app's data-access boundary — `src/infrastructure` owns how the app reaches a backend

## Local Contracts

Deployment target, the standing rule:

- This project works against **production `diligent-mink-756`** directly. No dev deployment is part of the workflow
- `CONVEX_DEPLOYMENT=prod:diligent-mink-756` in `.env.local` is the single source of truth. `npx convex deployment select` rejects a prod target ("Selecting a production deployment is unsupported") — never try to persist it that way
- Team `mcmarsh-fif-gmail-com`, project `cliefview-school`. The retired personal dev deployment was `striped-hyena-169`; do not reintroduce it
- Develop live against prod with `npx convex dev --prod`. `--prod` is a hidden flag and does not appear in `npx convex dev --help`. Plain `npx convex dev` reconfigures a _dev_ deployment — do not run it
- Per-command override when needed: `--deployment diligent-mink-756`
- `npx convex deploy` targets prod regardless of the env var

Because prod is the working target, ordinary commands are production actions:

- Announce the target before any deployment-affecting command: `target: prod (diligent-mink-756, project default production)`
- Get a fresh explicit yes in the current session before `npx convex dev --prod`, `npx convex deploy`, `npx convex env set` / `env remove`, a mutating `npx convex run`, `npx convex import`, or `npx convex export`. Consent never carries across actions or sessions
- Safe without asking, read-only: `npx convex env list`, `npx convex data`, `npx convex logs`, `npx convex function-spec`, `npx convex insights`
- Convex MCP: default to a non-prod selector. A read-only prod audit passes `--cautiously-allow-production-pii` alone; `--dangerously-enable-production-deployments` only when the user asks to change prod in that session. Never pair them by default
- Read-only mode, once the user requests it, is absolute for the session
- There is no dev sandbox in front of prod: the first push applies schema changes to live data, and a destructive schema change can drop it. Rehearse risky schema or migration work on a preview deployment first
- A push that "changed nothing" means the wrong deployment was hit — re-check the target, do not re-run the push

Code rules:

- `convex/_generated/` is generated — never hand-edit. Regenerated by `npx convex dev --prod` and `npx convex codegen`
- `convex/_generated/ai/guidelines.md` is Convex's own function-authoring guidance (targets `^1.44.0`); follow it when writing functions here
- `npx convex codegen` regenerates `_generated` **without** changing the deployed function surface, despite printing an "Uploading functions" line. Use it after adding a function so `api.*` types resolve; it is not a push and needs no gate
- Installed version is `convex@^1.45.0`

Data model — 18 tables, all live on prod:

- Content: `modules`, `moduleObjectives`, `lessons`, `assets`, `lessonAssets`
- People: `phases`, `users`, `enrollments`, `lessonProgress`, `assessmentAttempts`
- AI review: `aiGenerations`, `aiQuestions`, `aiQuestionOptions`, `aiReviewDecisions`
- Analytics: `progressEvents`, `monthlyRollups`, `counters`, `auditLog`

Schema rules that must hold:

- **Content and per-learner state are different tables.** Never put progress, completion, or a learner cursor on a content row. The old seed stored one hypothetical learner's `progressPercent` / `isCurrent` / `isComplete` on the shared module and section, which is why a lesson's editorial publish state was computed from whether a demo user had finished it
- **Nothing derivable is stored.** Lesson counts, asset counts, compliance percentages and averages are computed from indexed rows, or read from `counters` when the source table grows without bound. Do not re-add a `sectionCount`-style field: the original disagreed with the real lesson list on seven of nine modules and nothing recomputed it
- **Editorial state is `publishState` (`draft | published | archived`)** on modules, lessons, and assets. `locked` is never stored — it is derived at read time from `modules.sequence` plus the caller's enrollments
- **Ordering** lives in `order` (and `modules.sequence`), always read through a `by_<parent>_and_order` index so the database returns sorted rows. Reorders are a dense 1..N renumber inside one transaction via `convex/lib/ordering.ts`
- **Addressing:** modules by `slug`; lessons by module-scoped `slug` (`by_moduleId_and_slug`) so existing learner URLs survive — lesson slugs are NOT globally unique; assets and users by `Id<>`
- **Timestamps, not prose.** `contentUpdatedAt`, `lastActiveAt`, `lastAccessedAt`, `durationMinutes`, `monthlyRollups.monthKey` (`"YYYY-MM"`). All display formatting belongs in `src/application`
- **`auditFields` is just `contentUpdatedAt`.** "Who changed this" lives in `auditLog`; do not add `createdBy`/`updatedBy` back onto content rows — it duplicates the audit trail and would return an admin identity string from every public read
- Index names list every field in order: `["moduleId", "order"]` becomes `by_moduleId_and_order`
- Never read the wall clock in a query. `dashboard.adminOverview` takes `now` as an argument

Function surface:

- Public queries: `modules.listForAdmin`, `modules.adminDetail`, `lessons.adminDetail`, `assets.adminDetail`
- Internal queries: `dashboard.adminOverview`
- Helpers in `convex/lib/`: `authz.ts` (`getActor`, `requireStaff`, `requireAdmin`), `ordering.ts`, `audit.ts`, `counts.ts`, `time.ts`
- Shared validators in `convex/validators.ts`, mirroring the unions in `src/domain/academy/entities.ts`

Authentication and authorization:

- **Convex Auth** (`@convex-dev/auth`, email + password). It is a library, not a Convex component, so it needs no `convex.config.ts` entry — its tables are spread into our own schema via `...authTables`
- `convex/auth.config.ts` sets the JWT issuer to `process.env.CONVEX_SITE_URL`. If this file is missing or its domain is wrong, `getUserIdentity()` returns null forever and the app is silently always-signed-out with no error anywhere. Never hardcode the value, and never declare `CONVEX_SITE_URL` in `convex.config.ts`
- **`users` is both the staff profile and the auth user table.** `createOrUpdateUser` in `convex/auth.ts` never inserts — it resolves a sign-in to a pre-provisioned row by email and returns that id, which is what lets `users` keep its required fields
- **`convex/auth.ts` is the whole sign-in security model.** Every rule about who may sign in lives in that one callback: an unknown email is refused so nobody self-registers into the school; an inactive profile is refused; and a privileged profile (`smt_admin`, `super_admin`) is refused unless an operator has opened a single-use window with `internal.auth.allowAdminClaim`. Add rules there, not in the UI
- Admin provisioning: `npx convex run auth:allowAdminClaim '{"email":"...","minutes":30}'`, then the admin signs up with that email inside the window. `auth:claimStatus` reports provisioning state. Both are internal
- Authorization goes through `convex/lib/authz.ts` only: `getActor` resolves identity via `getAuthUserId` (never a client-supplied id, never a parsed token string), `requireStaff` demands an active profile, `requireAdmin` demands an admin role
- Every admin query calls `requireAdmin` first. The four content queries are admin-gated rather than staff-gated because they expose draft and archived content; learner-facing content queries arrive in Phase 8 and will filter on `publishState` instead
- `auth.viewer` returns null rather than throwing when unauthenticated, because the UI gate uses it to decide what to draw. It exposes only the caller's own name, initials, job title and role
- Every mutation calls `requireAdmin` first, from its first commit
- No file download URL is served from a public query. `ctx.storage.getUrl` in a query keyed by a client-supplied id would hand a signed link to any caller who can guess a module slug; serving lands in Phase 6 with the privacy decision
- Prod environment variables: `JWT_PRIVATE_KEY`, `JWKS`, `SITE_URL`. Generate the keys **headlessly** with `jose` — the interactive `npx @convex-dev/auth` wizard needs a TTY and hangs in a non-interactive session — and set them with the `NAME=VALUE` form (`npx convex env set "JWT_PRIVATE_KEY=$JWT"`), never `env set NAME "$VAL"`, because the key starts with `-----BEGIN` and the CLI reads the leading dash as a flag. `SITE_URL` is currently `http://localhost:8081` and **must be repointed at the deployed origin** when the frontend ships

Seed contract (`convex/seed.ts`, `convex/seed/data.ts`):

- `internal.seed.run` is an **idempotent `internalMutation`**, not `npx convex import`. The seed performs cleanup rather than transcription, and slug-to-id resolution is natural in a mutation
- Guards: `internalMutation` (unreachable from any client), a required `confirm: "cliffview"` argument, and `mode: "reset"` which refuses populated tables unless `iAmSure: true` is also passed
- Idempotency keys are natural keys: phase order, user email, module slug, (moduleId, lesson slug), (moduleId, asset title). Re-running `insert-missing` inserts nothing
- `convex/seed/data.ts` now owns the nine module slugs and all seed prose. It is a deliberate copy of `src/infrastructure/academy/in-memory-academy-repository.ts` because `convex/` cannot import `@/domain`; Phase 8 deletes the in-memory repository, leaving this the only copy
- The seed **derives** `users.compliancePercent` and the `counters` values from the enrollment rows it writes. Never seed an aggregate directly — that is how the old numbers came to contradict their own rows
- `monthlyRollups` are anchored to the month the seed runs, so the six-month dashboard window is always populated. The final month carries the true completion count so the overview tile and the last trend bar agree
- Take a snapshot before any schema-affecting push from here on: `npx convex export --path backups/<name>.zip`. `backups/` is gitignored — snapshots hold real staff data and must never be committed

Current state:

- The React app does not import Convex anywhere. Every route still renders from `src/infrastructure/academy/container.ts`
- Prod holds seeded data: 5 phases, 4 users, 9 modules, 44 lessons, 36 assets, 55 lesson-asset links, 20 enrollments, 2 AI questions, 6 monthly rollups
- `lessonProgress`, `assessmentAttempts`, `progressEvents`, `aiGenerations`, `aiReviewDecisions` and `auditLog` are intentionally empty until the phases that write them
- No `convex/convex.config.ts`, and none is needed: Convex Auth is a library rather than a component. Add one only when a real `@convex-dev/*` component or a typed env var is introduced

## Work Guidance

- Prefer the bundled `convex-*` skills over memory: `convex-design` for schema and functions, `convex-deploy-guard` before any deployment-affecting command, `convex-docs` for version-current API details, `convex-reviewer` and `convex-authz` before shipping
- Write schema and functions, typecheck, then ask for consent to push — in that order
- **Convex is the port.** There is no hand-written repository in front of it: route loaders call `convexQuery`, route components call `useSuspenseQuery`, and `src/application` presenters turn documents into view-models. Shared components in `src/components` stay prop-driven and never import Convex. Decision and phasing: `ADMIN_BACKEND.md`
